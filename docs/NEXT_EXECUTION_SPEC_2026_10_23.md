## 5. N1: 코드 기준 사본과 E: 감사 인수

### 코드 사본 판정

- 첫 커밋·remote·브랜치·HEAD·미커밋 변경을 함께 비교한다. 최신 파일 수정시간만으로 기준 사본을 선정하지 않는다.
- 같은 프로젝트라도 서로 다른 브랜치나 미커밋 변경은 병합 검토 대상으로 보존한다.

- 동일 파일은 패키지·백업·독립 프로젝트에서 의도적으로 필요할 수 있다. 해시 일치만으로 프로젝트 폴더를 옮기지 않는다.

### E: 처리 순서

1. 중앙 담당의 기존 전체 SHA/분기 대조 결과를 먼저 인수한다. 동일 범위의 두 번째 전수 해시 실행기를 만들지 않는다.
2. 10-24 17:30 정숙·18:00 검증, 10-25 10:00은 과거 예정 일정이다. 실제 실행·종료·성공 여부는 기존 terminal과 단계별 결과로 인수하며, 예약 시각 경과를 실행 완료의 증거로 삼지 않는다. 새로 지정된 독점 창이 있으면 그 창에서 이 작업의 E: 접근은 없다.
3. 10-25 10:00 경과 자체를 재개 허가로 사용하지 않는다. 정확한 중앙 종료 상태·단계별 근거·현재 점유·작업 범위를 확인한다.
4. 승인된 기존 감사 결과를 재사용하고, 빠진 범위만 기존 실행기의 단일 I/O 계약에서 보완한다.
5. DB/WAL/SHM은 정지 상태의 한 세트로 처리한다. DB 전수 해시는 다른 부하와 병행하지 않는다.

## 6. N2: 실데이터 계약과 원천 매핑

현재 개발 JSON 형식은 실제 원천 Manifest를 확인해서 만든 형식이 아니다. 원천 형식이 다르면 기존 원천 Manifest를 보존하고 최소 변환 어댑터로 연결한다.

| 계약 필드 | 필요한 정의·근거 | 미확정 시 처리 |
|---|---|---|
| source/table | 정확한 원천·버전·테이블 또는 승인 CSV | 유사 파일 자동 선택 금지 |
| target | 시장거래가/낙찰가 등 가격 종류, 원/만원 등 단위 | 숫자 크기로 단위 추정 금지 |
| transaction_time | 거래·낙찰 시각의 열과 정밀도 | 수집시각을 거래시각으로 대체 금지 |
| observed_at | 우리 시스템이 실제 관측한 시각 | 거래일+임의 일수 생성 금지 |
| published_at/known_at | 제공처 발표·인지 근거 | PIT 적격성 미확보로 표시 |
| group_key | 단지/필지/PNU와 물건 유형별 범위 | 거래 ID나 행 순번을 단지키로 대체 금지 |
| area | 전용/공급/연면적과 단위 | 서로 같은 면적으로 매핑 금지 |
| cancellation | 실제 해제·정정 코드와 날짜 의미 | 코드 의미 미확정 행의 자동 확정 금지 |
| transaction_key | 원천의 안정적인 거래 식별자 | 재수집 순번 기반 ID를 안정키로 가정 금지 |
| features | 설명·단위·사용 시점이 확인된 명시 목록 | 모든 수치형 열 자동 투입 금지 |

`pb_collect_molit_multikey.py` 코드에서 `trade_raw(deal_id, lawd_cd, deal_ymd, payload, collected_at)`는 확인했다. 이것만으로 payload 내부 타깃·단지키·실제 거래일이나 공개시각을 확정하지 않는다. 특히 `deal_ymd`는 조회 월 의미와 개별 거래일 의미를 구분해 확인한다.

### 검증 규칙

1. 기존 Runbook의 규칙·단위·정정 처리와 허용 오류율을 인수한다. 개발 기본값을 운영 정책으로 승격하지 않는다.
2. 가격 양수·유한값, 면적 종류별 범위, 유효일, 건축연도, 해제/정정 상태, 키 결손을 검사한다.
3. 같은 행의 여러 위반은 오류율에서 한 번만 센다. 위반 종류별 건수는 별도로 보존한다.
4. 동일 거래키의 동일 버전과 후속 정정을 구분한다. 보존할 버전을 원천 계약으로 결정하고 임의 drop_duplicates로 최신 정정을 지우지 않는다.
5. 허용치 경계·빈 데이터·타입 변환 실패·매핑 충돌을 시험한다. 식별자 선행 0과 원래 결측을 보존한다.

## 7. N3: 기존 중앙 실행기의 admission 연결

현재 Windows 실데이터 CLI는 `BLOCKED_OPERATIONAL_ADMISSION_REQUIRED`로 종료한다. 기능 구현 후 시험 통과만으로 이 차단을 제거하지 않는다.

### 연결 지점

- `real_data_eval.run`: 현재 Windows의 일괄 거절 분기를 기존 승인 실행기의 호출 계약으로 연결한다.
- `data_locator.resolve_data_root`: 실제 데이터 open 직전에 E: 정본·경로 alias 여부를 확인한다. import 시 데이터 드라이브에 접근하지 않는 동작은 유지한다.
- `sync_from_external_drive`, Step0: 기존 repo-local 복제를 되살리지 않는다. 필요한 경우 승인된 E: 파생 목적지와 기존 수집/적재 실행기에 연결한다.
- `avm_paths`: DATA_ROOT/DB_PATH/LEDGER_PATH 이름과 VWorld 하위폴더 의미를 유지한다.
- Phase7 세 파일: 예약·runner·실제 호출 근거를 먼저 확인한다. 활성 파일만 경로 변경하고 과거 파일은 운영 검증 완료에 포함하지 않는다.

### 실행 계약

1. 작업별 정확한 source/target/stage와 적용 코드 revision을 기존 실행 계약에 결속한다.
2. 유효한 최신 공지와 해당 event/revision/root에 맞는 작업별 receipt, 콘텐츠 PASS를 확인한다. 기존 PENDING receipt를 고쳐 쓰지 않는다.
3. 기존 단일 I/O lease·runtime 검사·새 NTFS121/140 감시를 사용한다. 별도 잠금 공급자나 자동 재시도 사슬을 신설하지 않는다.
4. 승인 범위·점유·상태를 데이터 open 전과 기존 계약의 필수 경계에서 다시 검사한다.
5. 원천은 읽기 전용으로 열고 승인된 파생 결과만 기준 루트 아래 정확한 목적지에 기록한다. C:/D: 운영 데이터 대체 적재는 없다.

### 인수 기준

실제 source open 이전에 무권한/잘못된 경로/점유가 차단되는 직접 반례, 만료·철회·쓰기 실패 시 결과 승격 차단, 자기 소유 lease 정리 근거를 확보한다. 기존 승인 경계를 흉내 낸 임의 환경변수나 합성 권한을 운영에 쓰지 않는다.

## 8. N4: 실평가 전 하네스 보완

### 현재 구현에서 이어갈 항목

1. N2의 실제 규칙과 거래 버전 처리를 하네스 앞단에 연결한다. 현재 positive-price/date/key 개발 기본 규칙만으로 운영 적격성을 선언하지 않는다.
2. train/validation/test는 70/15/15 기본 제안을 쓰되, 실제 시각 정밀도와 분포에 맞는 경계를 확정한다. 같은 날짜가 두 구간을 가르면 명시적 날짜 경계를 선택한다.
3. 시간 보간·결측치 대체·인코딩·선택은 학습 구간에서 fit한다. 타깃·시각·단지키·평가 시점 이후 정보는 특성에서 제외한다.
4. 그룹 겹침이 있으면 무작정 행을 버리지 않는다. 신규 단지 일반화 평가와 기존 단지 미래 거래 평가 중 어떤 목표인지 정하고 분할 계약을 고정한다.
5. 후보 7개 모델의 비교/선택은 validation으로 끝낸다. 현재 모든 모델의 test 합격을 묶는 집계는 실운영 평가 목적에 맞는 선택 모델 게이트로 보완한다.
6. 최종 test는 선택·튜닝이 끝난 모델을 1회 평가한다. test 결과를 본 뒤 같은 test로 특성을 조정하고 다시 최종 성능이라 부르지 않는다.
7. 괴리율은 기존 `abs(actual-predicted)/actual*100` 정의를 재사용한다. 단위·모집단·분할이 다른 PoC와의 단순 증감을 성능 개선으로 해석하지 않는다.

### 지표와 보고

R², MAPE(%), MAE(타깃 단위), 평균/중앙 상대괴리율, 구간별 표본수와 누수 플래그를 기록한다. 기존 목표는 R² > 0.84, MAPE < 10.5%다. 이 값은 운영 배포 자동 승인 기준이 아니며 최종 업무 합격선과 구분한다.

### 인수 기준

정답 복제·미래 지표·동일 거래 재유입·단지키 결손·동일 날짜 경계 반례를 잡는다. 검증셋 모델 선택이 최종 test 정답과 독립적임을 확인한다. 관련 변경의 최종 합동 시험은 한 번 수행하고 실패 영향 범위만 재검사한다.

## 9. N5: 실데이터 실행과 저장 재조회

1. 기존 승인 범위에서 최소 한 테이블/한 대상 범위를 고정한다. 데이터 규모는 먼저 재측정하며 전수 학습 시간을 사전에 보장하지 않는다.
2. source revision·범위·규칙 버전·코드 commit·분할 경계를 결과에 결속한다.
3. 원천 읽기→명시 매핑→검증→분할/감사→validation 선택→최종 평가→승인 결과 저장을 기존 실행기 안에서 수행한다.
4. 새 읽기 연결로 저장 결과를 재조회해 run ID·입력 지문·표본수·선택 모델·지표·상태가 일치하는지 확인한다.
5. 원천 변경·입력 지문 불일치·누수·무권한·잠금·저장 실패가 있으면 부분 결과를 보존하고 완료 승격을 차단한다.

완료는 실제 테이블 한 범위의 전 경로가 일치할 때 인정한다. 운영 배포, 전국 재학습, 기존 운영 모델 교체는 이 인수와 별개다.

## 10. N6~N7: KRERI 학습용 지표 보강

### 확인된 출처와 남은 조건

공식 검색 결과의 [/32](https://kreri.re.kr/32)는 용역보고서 게시판이다. [/42](https://www.kreri.re.kr/42)는 감정평가지표·지수 게시판으로 지가변동률·공시가격 변동률 등 지표 후보가 확인됐다. 게시판 종류는 검색 색인 근거이며 실제 첨부 표·파서 검증의 대체물이 아니다.

사용자가 확정한 목적은 AVM 학습용 지표·특성 보강이다. 이 목적에 맞는 통계표를 우선 후보로 검토한다. 용역보고서의 문장을 바로 숫자 피처로 생성하지 않는다.

HEAD 요청은 200이었으나 본문 GET·robots는 403이었다. 이용 조건과 실제 첨부 형식은 아직 확인하지 못했다. 정상 접근 또는 정식 제공 자료로 확인하고, 403 우회·로그인 우회·검색 캐시를 이용한 일괄 수집은 하지 않는다.

### 표준 지표 레코드

| 항목 | 내용 |
|---|---|
| source_url/source_id | 공식 원문과 제공 자료 식별자 |
| indicator_code/name | 정의가 확인된 지표 코드·명칭 |
| region_code/level | 시도/시군구 등 지역 수준과 코드 체계 |
| period_start/end | 지표가 설명하는 기간 |
| published_at | 해당 값이 처음 공개된 실제 시각·근거 |
| observed_at | 이번 시스템 취득 시각 |
| revision | 개정·수정본 식별자 |
| value/unit | 원값과 %, 지수 기준연도 등 단위 |
| file_sha256/parser_version | 파일 지문과 재현 가능한 변환 버전 |
| usage_basis | 허용된 이용 범위 근거 |

### 수집과 피처 결합

1. 정상 샘플 한 개와 이용 조건을 확인한 뒤 기존 HTTP 오류 분류 모듈을 사용하는 파서를 구현한다.
2. 순차 요청·지연·제한 재시도·URL/해시 기반 중복 방지·resume를 사용한다. 인증 오류는 2, 구조 오류는 3, 일시 실패 소진은 기존 규약대로 기록한다.
3. 원본과 파생값은 승인된 E: 정확 목적지에 보존한다. 확정 전 별도 C:/D: 수집 DB나 스케줄러를 만들지 않는다.
4. 가격 기준 시점에 발표돼 있었던 revision만 as-of 결합한다. 최근 개정치를 과거 거래에 소급 결합하지 않는다.
5. 발표일이 없는 통계는 피처 후보로만 보존하고 과거 평가 적격성 미확보를 표시한다. 발표 지연일을 임의로 생성하지 않는다.
6. N5에서 test를 이미 개봉했다면 같은 test로 지표 추가 효과를 다시 최종 판정하지 않는다. validation 탐색과 별도의 미개봉 확장 holdout을 구분한다.

인수 기준은 승인 샘플의 독립 수치 대조, 단위·지역·기간·개정 보존, 재실행 중복 다운로드 0, 미래 공개 자료 결합 0, 기존 기준모델 대비 validation 결과와 새 holdout의 최종 결과다.

## 11. N8: 정리 후보 제한 처리

N8은 후순위다. 현재 발견한 미커밋 저장소를 정리하지 않으며, 기준 사본을 확정하기 전 폴더 이름 정리나 경로 자동 수정도 하지 않는다.

대상별 보존본·상이 브랜치·미커밋 변경·실제 참조를 확인하고 승인된 목록에 한해 처리한다. AVM 데이터는 E: 원본 보존 복사와 수·크기·해시 검증 계약을 지킨다. 격리 이동 역시 DB·활성 코드 경로를 깨뜨릴 수 있으므로 단순한 가역 작업으로 취급하지 않는다. `탱커펀드` 제외와 기존 HOLD 보존 조건을 유지한다.

산출물은 승인 대상표, 보존 근거, 원위치/격리 위치 원장, 기능 영향 확인, 실제 전후 용량이다. 영구 삭제를 이번 명세 작성이나 이전 해시 일치만으로 실행하지 않는다.

## 13. 중단 상태의 정확한 구분

| 상태 | 의미 | 다음 조치 |
|---|---|---|
| BLOCKED_E_PRIMARY_NOT_MOUNTED | E: 부재/쓰기 불가 등 기준 루트 조건 미충족 | D:/C: 대체 없이 장치 조건 복구 |
| BLOCKED_E_IO_BUSY | 다른 E: 고부하/공용 lease 점유 | 새 실행 없이 기존 작업 종료·허용 창 확인 |
| BLOCKED_E_WRITE_FAILING | 새 NTFS140/오류121 관측 | 자기 작업 중단·원천/증거 보존, 자동 재시작 금지 |
| BLOCKED_CONTENT_VERIFICATION_PENDING | 유효 공지의 콘텐츠가 PENDING | 공지 READY/freeze RELEASED와 구분, 신규 PASS/작업 receipt 필요 |
| BLOCKED_OPERATIONAL_ADMISSION_REQUIRED | 실제 실행기의 작업별 허가 연결 미완료 | N3 구현·기존 제공자 인수 |
| INPUT_CONTRACT_UNRESOLVED | 타깃/시각/키/Manifest/Runbook 미확정 | N2 원천 정의 인수 |
| SOURCE_ACCESS_OR_TERMS_UNRESOLVED | KRERI 본문/사용 조건/첨부 미확인 | N6 정상 자료 확인 |
| LEAKAGE_SUSPECTED | 타깃/그룹/미래 정보 누수 반례 | test 개봉 보류·N4 계약 재검토 |

읽기 전용 검증 프로세스는 writer와 구분해 `AVM_VERIFICATION_PROCESS_ACTIVE`로 기록한다. 레거시 D:/C: HOLD 표식만으로 중앙 동결 미해제라고 보고하지 않는다. 동일 상태의 반복 보고 대신 새 오류·상태 전환·완료를 보고한다.

## 14. 명세 검토 결과

1. 과거 D:/F: 탐색·mtime 선택·repo 데이터 fallback은 최신 사용자 E: 정책과 충돌하므로 후속 실행에서 사용하지 않는다.
2. 코드 감사의 약 117.53MiB를 실제 공간 회수나 TB 단위 데이터 중복 해결로 보고하지 않는다.
3. 현재 JSON 매핑/개발 규칙은 실제 원천 계약이 아니다. N2가 끝나기 전 실자료 적격성을 확정하지 않는다.

### 16.4 완료·실패·복구 기준

| 상황 | 결과 판정 | 처리 |
|---|---|---|
