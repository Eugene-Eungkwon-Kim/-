# 🔬 Phase A 착수 결과 보고서 — 정직한 베이스라인 측정

**작성일**: 2026-06-18
**작업**: R²≥0.95 계획 Phase A 착수 (누수 감사 + 정직한 베이스라인 측정)
**결론**: ⚠️ **현재 데이터로는 어떤 정직한 모델도 학습 불가. 실데이터 확보가 유일한 진입점.**

---

## 1. 무엇을 했나

R²≥0.95 계획서의 Phase A 첫 관문대로, **숫자를 만들기 전에 검증 도구부터** 구축하고 현재 데이터의 진짜 실력을 측정했습니다.

- ✅ `scripts/leakage_audit.py` — 누수 감사 도구 (작동 검증 완료)
- ✅ `scripts/temporal_split.py` — 시간 기반 분할 평가 (실데이터용 인프라)
- ✅ 현재 데이터셋 2종에 대한 정직한 베이스라인 측정

---

## 2. 측정 결과 (충격적이지만 중요함)

### 2-1. `sample_npl_data.csv` — 누수 의존 확인

| 특성셋 | R² | 해석 |
|--------|-----|------|
| 누수 특성 포함 (appraised_price 등) | **0.845** | 가짜 — 가격이 가격을 예측 |
| `appraised_price` 제거 | 0.483 | 0.36 급락 |
| `final_sale_price` 제거 | 0.605 | 0.24 급락 |
| **누수 완전 제거 (물리속성만)** | **-0.22** | **신호 없음** |

➡️ 보고되어 온 "정직한 0.78"조차 **실제로는 누수의 산물**이었습니다.
누수를 완전히 걷어내면 R²는 **음수(-0.22)** — 평균값 예측보다 못합니다.

### 2-2. `real_estate_combined_20260617.csv` — 신호 자체가 없음

```
전체 특성 GradientBoosting R² = -0.0379
```

➡️ Phase 4에서 "R²=0.7825" 보고의 근거였던 이 합성 데이터는,
실제로는 **시장가와 어떤 특성도 관계가 없는 난수 덩어리**였습니다.

---

## 3. 핵심 결론

```
합성 데이터의 두 가지 상태:
  (A) sample_npl_data    → 누수로만 R²가 나옴, 걷어내면 -0.22
  (B) real_estate_combined → 누수도 신호도 없음, R² ≈ 0

→ 둘 다 R²≥0.95는커녕 R²>0 의 정직한 근거가 될 수 없음.
```

**이것은 실패가 아니라, 검증 프레임워크가 제 역할을 한 결과입니다.**
도구가 없었다면 우리는 "0.78 정직 모델"을 믿고 클라우드에 배포해
실전에서 음수 R²로 무너지는 것을 목격했을 것입니다.

---

## 4. 0.95 목표에 대한 솔직한 재평가

| 전제 | 상태 |
|------|------|
| 합성 데이터로 0.95 | ❌ 불가능 (수학적으로 신호가 없음) |
| 실데이터로 0.85~0.92 | ✅ 가능 (업계 수준, 단 데이터 확보 시) |
| 실데이터로 0.95 | ⚠️ 도전 영역 (comparable 모델 + 엄격 검증 필요) |

> **0.95는 데이터 문제이지 모델 문제가 아닙니다.**
> 모델·앙상블·하이퍼파라미터는 데이터에 신호가 있을 때만 의미가 있습니다.

## 6. 준비 완료된 자산 (실데이터 도착 즉시 가동)

| 도구 | 상태 | 역할 |
|------|------|------|
| `leakage_audit.py` | ✅ 작동 검증 | 누수 vs 진짜 구별 |

```bash
python scripts/temporal_split.py --data <실데이터> --target 거래금액 --time-col 거래일
python scripts/leakage_audit.py  --data <실데이터> --target 거래금액 --time-col 거래일
```

## 7. 권고

1. **즉시**: Data.go.kr 실거래 API 키 확보 (0.95의 절대 전제)
