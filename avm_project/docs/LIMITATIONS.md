**작성일**: 2026-06-30
**대상**: Loan4U AVM Engine v1.0-ensemble
**목적**: 현재 모델 성능 지표의 실제 의미를 왜곡 없이 기록한다.

## ⚠️ 한 줄 요약

> **현재 R²=0.98은 "실거래 예측 정확도"가 아니다.**
> 자기가 만든 공식으로 합성 데이터를 생성하고 그 데이터를 다시 학습한
> **순환(circular) 결과**이며, 실제 한국 부동산 시장 일반화 성능과 무관하다.

## 1. 데이터의 본질: 합성(Synthetic), 실거래 아님

### 1.1 현재 상태
- `data/raw/KR_data.csv` (10,000행)는 `generate_kr_realistic_data.py`가
  **사람이 정한 공식**으로 만든 가상 데이터다.
- 국토교통부 실거래가 API(Data.go.kr) 데이터는 **현재 0건** 확보.
  (원격 실행 환경의 네트워크 정책이 `apis.data.go.kr` 도메인을 차단 →
  로컬 수집 스크립트 `collect_kr_data_local.py` 실행 대기 중)

### 1.2 왜 R²가 높을 수밖에 없는가 (순환성)
```
가격 공식 정의  →  공식으로 데이터 생성  →  같은 패턴을 모델이 학습
                                                  ↓
                              모델이 공식을 거의 복원 → R² 0.98 (당연)
```
이것은 모델 성능이 아니라 **"공식을 공식으로 맞췄다"**는 동어반복에 가깝다.

## 2. 정량적 증거: 강건성 검증 결과

`scripts/validate_robustness.py` 실행 결과 (`output/robustness_report.json`):

### 2.1 선형 베이스라인 대비 — 앙상블이 거의 무가치
| 모델 | 홀드아웃 R² |
|------|-------------|
| 단순 선형회귀 (LinearRegression) | **0.9977** |
| 3-모델 앙상블 (XGB+LGB+GB) | 0.9983 |
| **실질 우위** | **+0.06%p** |

> 합성 데이터가 거의 선형이라 **단순 선형모델로도 동일한 성능**이 나온다.
> 비싼 앙상블·GPU 학습·NPU 변환은 이 데이터에선 정당화되지 않는다.
> 높은 R²는 데이터가 쉬워서지, 모델이 똑똑해서가 아니다.

### 2.2 노이즈 강건성 — 표면적 패턴
| 입력 노이즈 | R² | MAPE |
|------------|------|------|
| 0% | 0.996 | 2.4% |
| 5% | 0.975 | 5.7% |
| 10% | 0.961 | 8.8% |
| 20% | 0.900 | 15.5% |
| 30% | 0.797 | 22.2% |

> 실거래에는 항상 5~15% 수준의 설명 불가 변동(개별 협상, 급매, 층/향 차이)이
> 존재한다. 그 수준 노이즈만으로 MAPE가 목표(10.5%)를 초과 → 현재 정확도는
> 깨끗한 합성 데이터에서만 성립.

### 2.3 피처 중요도 — old_price 단일 지배 (`feature_importance_report.json`)
| 피처 | 순열 중요도(3모델 평균) |
|------|------------------------|
| **old_price** | **0.987** |
| area_sqm | 0.005 |
| latitude | 0.005 |
| longitude | 0.003 |
| property_type | 0.000 |

피처 격리 실험 (GradientBoosting):
| 입력 구성 | 홀드아웃 R² | MAPE |
|-----------|-------------|------|
| old_price 단독 | **0.997** | 2.7% |
| 펀더멘털만 (면적·위경도·층·연식, old_price 제외) | **0.857** | 17.4% |

> **핵심**: 헤드라인 R²=0.98은 거의 전부 `old_price → new_price` 대리효과다.
> 합성 생성 시 `old_price = new_price × uniform(0.88,0.98)`로 만들어
> old_price가 정답의 ~93% 스케일 사본이 되었다(준-누수, leakage-like).
>
> "물건 특성만으로 가치를 평가하는 능력"의 진짜 지표는 **펀더멘털 R²=0.857**이며,
> 이마저 MAPE 17.4%로 목표(10.5%)를 초과한다. 즉 위치·면적 모델은 신호는
> 있으나 아직 부정확하다. 실거래 AVM은 **직전가 없이도** 평가할 수 있어야 하므로
> 이 0.857이 0.98보다 정직한 성능 지표다.

### 2.4 분포 외(OOD) 입력 — 가드레일 부재
| 입력 | 예측 | 문제 |
|------|------|------|
| 가격 0원 | 2.82억 | 0원 입력을 거부하지 않고 외삽 |
| 해외 좌표(위도 45) | 5.51억 | 한국 밖인데 가격 산출 |
| 초고가 100억 | 35.85억 | 정규화 클리핑으로 상한 왜곡 |

> 입력 검증이 없어 비정상 입력에도 그럴듯한 숫자를 뱉는다.
> 대출 심사 맥락에선 **조용한 오답이 가장 위험**하다.

## 3. 보정계수(correction factor)의 근거 부재

`avm_correction_layer.py` / `avm_auction_module.py`의 상수들:
- 지역×등급 보정 1.30, 1.20, 1.15 …
- 낙찰가 시장계수 rising 1.05 / normal 1.00 / declining 0.95

이 값들은 **Loan4U MASS 시스템 분석에서 가져온 가정값**이며,
실거래로 캘리브레이션된 것이 아니다. → 코드에 `ASSUMPTION` 주석으로 명시 예정.

## 4. 프로덕션 적합성 판정

| 항목 | 상태 |
|------|------|
| 코드 구조/모듈화 | ✅ 양호 (단일 책임, 타입힌트, 69 테스트) |
| 실거래 데이터 | ❌ 0건 |
| 일반화 성능 | ❌ 미검증 (합성 데이터만) |
| 입력 가드레일 | ❌ 없음 (OOD 무방비) |
| 보정계수 근거 | ⚠️ 가정값 |
| **대출 심사 투입 가능 여부** | **❌ 불가** |

> 현재는 **엔지니어링 골격(skeleton)이 완성된 상태**다.
> 파이프라인·API·테스트·변환 경로는 동작하지만,
> 그 위에 흐르는 데이터가 가짜이므로 **예측값을 신뢰해선 안 된다.**

## 5. 실거래 데이터 확보 후 달라지는 것

1. `collect_kr_data_local.py`로 국토부 실거래 수집 → `KR_data.csv` 교체
2. `train_kr_model.py` 재학습 → **이때 나오는 R²가 진짜 성능 지표**
3. 그 R²가 0.84를 넘으면 그제서야 의미 있는 모델
4. 선형 베이스라인 대비 우위가 커지면 앙상블이 정당화됨
5. 보정계수를 실거래로 캘리브레이션

**결론**: 지금의 0.98이 아니라, **실거래로 재학습한 뒤의 숫자**가 평가 대상이다.
이 문서는 그 전까지 현재 지표가 과대평가되지 않도록 하는 안전장치다.
