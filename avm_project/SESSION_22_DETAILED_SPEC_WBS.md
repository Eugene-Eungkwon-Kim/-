## 1. Track C: 매칭 표본 확대 (주소 파싱 개선)

### 목표
`onbid_auction_results` 검증셋(124건)의 동(umd_nm) 추출률을 56%(69/124)에서 90%+로 개선, 매칭 성공 표본을 32건 → 80건+로 확대.

### 문제 진단 필요 작업
1. 동 추출 실패 55건(124-69)의 `address_raw` 패턴 직접 확인
2. 실패 유형 분류 (예: "회원동3길 38" 같은 도로명 주소 혼재, 오탈자, 동 표기 누락 등)
3. 유형별 정규식 보강 또는 도로명→법정동 변환 필요성 판단

### 명세
- 신규 스크립트: `scripts/phase7_c_address_parser_v2.py`
- 입력: 실패 55건의 `address_raw`
- 출력: 개선된 파싱 규칙 + 재매칭 결과 (`results/phase7_c_match_improvement.md`)
- 완료 기준: 재실행 후 매칭 성공 표본 수(T1+T2) 증가폭을 실측 보고 (목표치 미달 시 그 이유도 명시)

### WBS

| ID | 작업 | 예상 소요 |
|---|---|---|
| C.1 | 파싱 실패 55건 원문 전수 확인 및 유형 분류 | 15분 |
| C.2 | 유형별 정규식/전처리 규칙 추가 | 30분 |
| C.3 | 재매칭 실행 및 표본 수 재측정 | 10분 |
| C.4 | 결과 보고 (개선 전/후 대조) | 10분 |

## 2. Track D: 낙찰가율 모델화

### 목표
검증B의 "낙찰가율 leave-one-out 단순평균" 대신, 기존 590건 학습 데이터(`p6_training_engineered.csv`)로 훈련한 낙찰가율 모델을 적용해 MAPE를 15.12%보다 낮춘다. **leak-free 원칙 필수 준수** (Track C에서 확보한 검증셋과 학습셋이 겹치지 않아야 함 — 실제로 onbid_auction_results 검증 표본과 p6 학습 데이터는 소스가 겹칠 수 있으므로 중복 제거 필요).

### 명세
- 신규 스크립트: `scripts/phase7_d_hammer_rate_model.py`
- 방법: `p6_advanced_hammer_ensemble.pkl`(기존 XGB+LGB+Ridge)을 낙찰가율 예측에 재사용하되, **Track C 검증셋과 학습셋 물건 ID 중복을 사전 제거**
- 출력: 그라운딩 시세 × 모델 예측 낙찰가율 vs 실제 낙찰가 MAPE
- 완료 기준: leak-free 홀드아웃 기준 MAPE 산출, 15.12%(leave-one-out 평균) 대비 개선 여부를 정직하게 보고 (개선 안 되면 그 사실도 그대로 보고)

### 리스크
- 검증셋(onbid 주거용건물)과 학습셋(p6, onbid 583건 포함)이 **동일 소스일 가능성 높음** → 중복 제거 안 하면 또 데이터 누수. **반드시 property id/case 기준 교집합 제거 후 진행.**

### WBS

| ID | 작업 | 예상 소요 |
|---|---|---|
| D.1 | 검증셋-학습셋 중복 물건 식별 및 제거 | 15분 |
| D.2 | 낙찰가율 모델 예측값 생성 (중복 제거된 검증셋 대상) | 15분 |
| D.3 | 그라운딩 시세 × 모델 낙찰가율 vs 실제 낙찰가 MAPE 산출 | 10분 |
| D.4 | 검증A/B/D 3방식 비교 보고 | 10분 |

## 3. Track E: 비아파트 자산 그라운딩 전략 (탐색)

### 목표
토지(152,007건)/상가(21,956건) RTMS 데이터로 아파트 외 자산(전체의 86%)에 그라운딩 적용 가능성을 탐색한다.

### 명세
- 신규 스크립트: `scripts/phase7_e_nonapt_feasibility.py`
- 방법: 토지 실거래 데이터의 매칭 키(지번만 존재, 단지명 없음) 확인 → NPL 토지/상가 물건과 지번 매칭 시도 → 매칭률만 우선 측정 (전체 예측기 구축은 매칭률이 유의미할 때만 진행)
- 완료 기준: 매칭률 실측. 매칭률이 낮으면(예: <20%) "이 방법은 비아파트에 부적합"이라고 명시하고 대안(예: 지역별 평당가 평균)을 제안하는 것으로 종료 — 억지로 구현하지 않는다.

### WBS

| E.1 | NPL 토지/상가 물건 지번 추출 (기존 정규식 재사용) | 10분 |
| E.2 | RTMS land_trade/commercial_trade 데이터 로드 및 매칭 시도 | 20분 |
| E.3 | 매칭률 측정 및 실행 가능성 판정 | 10분 |
| E.4 | 결과 보고 (Go/No-Go 판정 명시) | 10분 |

## 5. 원칙 (기존 Session 21 원칙 유지)

1. 모든 지표는 재실행 가능한 스크립트 출력만 인용
2. train/holdout 분리 없는 MAPE 보고 금지 — 특히 Track D는 검증셋-학습셋 중복 제거 필수
3. 목표 미달 시 그대로 보고 ("PASS 포장 금지")
4. 매칭률/실행 가능성이 낮으면 억지로 구현하지 않고 Go/No-Go로 명시
