## 2. WBS 검토 결과

### ✅ 강점

| 항목 | 평가 | 근거 |
|------|------|------|
| 계층 구조 | ⭐⭐⭐⭐⭐ | 1~6 단계, 각 20~30개 작업으로 적절히 분해 |
| 담당자 명시 | ⭐⭐⭐⭐ | 각 작업마다 담당자, 시간, 산출물 명확 |
| 검증 기준 | ⭐⭐⭐⭐ | SQL 쿼리, 테스트 케이스 제시 |

### ⚠️ 개선점

#### P1 (CRITICAL): 병렬 처리 시간 계산 재검증

```
문제: "병렬 처리로 72시간 → 15시간" 계산이 과도하게 낙관적
  
  현재 계산:
    ├─ 순차: 8,748 API 호출 × 0.3초 = 2,624초 = 44분
    ├─ 병렬(5개 worker): 44분 ÷ 5 = 8.8분
    └─ DB 적재 + 네트워크: +50분 = 약 1시간
    
  문제점:
    ├─ API rate limit이 전역(계정당)인데, 병렬로 호출하면 위반
    ├─ DB 적재 시간(bulk insert)을 무시함
    └─ 지역별 API 응답 지연 편차 미고려
  
  권장사항:
    ├─ 병렬 workers를 줄임: 5 → 2~3
    ├─ 예상 소요시간 재산정: 15시간 → 30~36시간
    ├─ 단순 순차: 72시간 유지 (안전)
    └─ 최종 선택: 병렬(3 workers) 기준 30시간 명시
```

#### P2 (HIGH): 모델 학습 시간 불확실성

```
문제: "모델 학습 20시간" 하드웨어 스펙이 없음
  
  현재 상황:
    ├─ CPU: 미명시
    ├─ GPU: 언급 없음
    ├─ 메모리: 4GB (사양서에만 있음)
    └─ 파이썬 버전: 미명시
  
  필요사항:
    ├─ 최소 사양: CPU 4코어, 8GB RAM, SSD 2GB
    ├─ 권장 사양: CPU 8코어, 16GB RAM, GPU (RTX 4060)
    └─ 예상 시간:
        - 최소 사양: ~20시간 (XGBoost + Ridge)
        - 권장 사양: ~10시간 (병렬화)
        - GPU: ~5시간 (XGBoost GPU 버전 사용)
  
  권장사항:
    "4.4 모델 학습" 섹션에 다음 추가:
    (4.4.0) 하드웨어 사양 확인
      □ CPU: 최소 4코어 (권장 8코어)
      □ 메모리: 최소 8GB (권장 16GB)
      □ 저장소: 최소 2GB 여유
      □ GPU: 선택사항 (있으면 2배 빠름)
```

#### P3 (MEDIUM): 검증 쿼리의 DB 종속성

```
문제: 쿼리들이 SQLite 방언을 사용하는데, PostgreSQL 마이그레이션 가능성 무시
  
  예시:
    SELECT count(*) FROM transactions
    WHERE transaction_key IN (
      SELECT transaction_key FROM transactions
      GROUP BY transaction_key HAVING COUNT(*) > 1
    );
    
  SQLite에서는 작동하지만, 대규모 데이터(870K)에서 성능 저하
  
  권장사항:
    "3.4 검증" 섹션 수정:
    
    SELECT transaction_key
    FROM transactions
    GROUP BY transaction_key
    HAVING COUNT(*) > 1;
    -- 더 간단하고 효율적
```

### 📝 WBS 개선안

```

  3.2 병렬 처리 시간 재산정 (15시간 → 30시간)
  4.4 모델 학습 시 하드웨어 사양 확인 추가
```
