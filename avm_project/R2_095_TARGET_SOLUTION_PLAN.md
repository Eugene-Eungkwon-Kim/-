# 🎯 R² ≥ 0.95 목표 달성 솔루션 개발 세부 계획서

**작성일**: 2026-06-17
**목표**: 정직한(누수 없는) 모델 기준 R² ≥ 0.95
**원칙**: 로컬 우선, 데이터 누수 절대 금지, 검증 게이트 통과 후 진행

---

## ⚠️ 0. 먼저 반드시 읽어야 할 기술적 경고

### 0-1. "우리는 이미 R²=0.9592를 본 적이 있다 — 그러나 그것은 가짜였다"

본 프로젝트 이력에서 **LinearRegression이 R²=0.9592**를 기록했습니다.
**이 수치는 데이터 누수(Data Leakage)로 판정되어 의도적으로 제거된 것입니다.**

```
누수 원인 (제거된 컬럼):
  ❌ final_sale_price   → 사실상 타겟 그 자체
  ❌ 가격 기반 집계변수  → 타겟 정보 유출
  
누수 제거 후 정직한 성능:
  ✅ LightGBM: R²=0.7825 (가장 안정적)
  ✅ GradientBoosting(튜닝): R²=0.7917
```

**결론: R²=0.95를 "쉽게" 만드는 유일한 방법은 우리가 방금 고친 그 버그를 다시 집어넣는 것입니다.**
이 계획서의 존재 이유는 **누수 없이** 0.95에 도전하되, 가짜 0.95를 진짜로 착각하지 않도록 검증 장치를 거는 것입니다.

### 0-2. 현실적 벤치마크

| 시스템 | 데이터 | R² (실측 기준) |
|--------|--------|----------------|
| Zillow Zestimate | 수천만 건 + 풍부한 특성 | ~0.90 |
| Redfin Estimate | 대규모 실거래 | ~0.88 |
| 한국부동산원 AVM | 국토부 실거래 | 0.85~0.92 |
| **본 프로젝트 (현재)** | **합성 샘플 3,000행** | **0.79** |

> 업계 최고 수준 AVM도 실측 기준 R²는 대개 **0.85~0.92**입니다.
> **미래 데이터에 대한 진짜 held-out R² 0.95는 "탁월함"을 넘어 "의심 대상"입니다.**

### 0-3. 현재 데이터의 천장 문제

현재 학습 데이터 3,000행은 **합성(synthetic) 샘플**입니다.
합성 데이터는 생성 규칙에 따른 인위적 상한이 있어, 여기서 나온 어떤 R²도 **실전 성능을 보장하지 못합니다.**

➡️ **0.95 도전의 첫 번째 전제조건은 "실제 국토부 실거래 데이터 확보"입니다.**

## 🎯 1. 목표 재정의 (정직한 단계별 목표)

무책임하게 "0.95 달성 가능"이라 단언하지 않습니다.
대신 **검증 가능한 단계 목표**로 분해합니다.

| 단계 | R² 목표 | 성격 | 달성 가능성 |
|------|---------|------|-------------|
| 현재 | 0.79 | 합성 데이터, 정직 | 달성됨 |
| **M1** | **0.85** | 실데이터 + 기본 특성 | 높음 (업계 하한) |
| **M2** | **0.90** | 실데이터 + 고급 특성공학 | 중간 (업계 상위) |
| **M3** | **0.93** | 외부 데이터 결합 + 앙상블 | 도전적 |
| **M4 (Stretch)** | **0.95+** | 비교사례(comparable) 모델링 | 매우 도전적, 누수 위험 高 |

> **M4(0.95)는 stretch goal입니다.** M1~M3를 누수 없이 통과하지 못하면 M4는 의미가 없습니다.
> M4에서 0.95가 나오면 **"성공"이 아니라 "누수 감사(audit) 발동"** 으로 취급합니다.

## 🔬 2. R²를 정직하게 끌어올리는 4대 레버

### 레버 1: 데이터 — 양과 질 (영향도 ★★★★★)

```
현재: 합성 3,000행 × 19특성
목표: 실거래 100,000~500,000행 × 40+특성

작업:
  • Data.go.kr 아파트/연립/단독 실거래 24개월 수집
  • 지역(시군구) 다양성 확보 — 특정 지역 편중 방지
  • 거래 유형 분리 (매매/전세/월세 혼합 금지)
  • 명백한 오류만 제거 (정상 분산은 보존 — 과도한 클렌징은 R²를 인위적으로 올리는 또 다른 누수)
```

**핵심 주의**: "이상치 제거"로 R²를 올리는 것은 위험합니다.
정상적인 시장 변동성까지 깎아내면 보고된 R²는 오르지만 **실전에서는 무너집니다.**

### 레버 2: 특성 공학 — 정직한 신호 추가 (영향도 ★★★★☆)

```
위치 (가장 강력):
  • 위경도 → 행정동/지하철역/CBD 거리
  • 시군구·읍면동 타겟 인코딩 (단, fold 내에서만 계산 → 누수 방지)

건물:
  • 층수, 건축연도, 전용면적, 방향, 주차, 세대수, 브랜드

시계열:
  • 거래 시점 시장지수, 계절성, 금리(외부)

❌ 절대 금지 (누수):
  • 같은 물건의 다른 거래 가격
  • 미래 정보 (예측 시점 이후 데이터)
  • 타겟에서 파생된 어떤 집계값
```

### 레버 3: 비교사례(Comparable Sales) 모델링 — 양날의 검 (영향도 ★★★★★ / 위험 ★★★★★)

실거래 AVM에서 R²를 0.90→0.95로 밀어 올리는 핵심 기법이지만 **누수의 온상**입니다.

```
올바른 방법 (누수 없음):
  • 예측 대상 거래 "시점 이전"의, "공간적으로 인접한" 거래만 사용
  • 엄격한 시간 컷오프 (t 시점 예측 → t 이전 거래만)
  • 같은 물건/같은 거래는 절대 제외

잘못된 방법 (누수 — 가짜 0.95 생산):
  • 미래 거래를 comparable로 사용
  • 같은 단지 동시점 거래 포함
  • 전체 데이터로 이웃 평균 계산 후 split
```

### 레버 4: 모델·앙상블 — 마지막 2~3% (영향도 ★★★☆☆)

```
• 하이퍼파라미터 최적화 (Optuna / Bayesian, GridSearch보다 우수)
• Stacking 앙상블 (GB + LGBM + XGB → Ridge 메타)
• 대규모 데이터 시 TabNet / 신경망 검토
• 분위 회귀로 예측구간 동시 제공
```

> 모델 교체만으로 0.79→0.95는 **불가능**합니다. 모델은 데이터·특성이 만든 신호의 상한 안에서만 작동합니다.

## 🛡️ 3. 누수 방지 검증 프레임워크 (이 계획서의 심장부)

**모든 R² 개선은 아래 게이트를 통과해야만 "진짜"로 인정합니다.**

### 게이트 A: 시간 기반 분할 (Temporal Split)

```
❌ 랜덤 K-fold 만으로 판단 금지
✅ 과거로 학습, 미래로 평가

   학습: 2024-01 ~ 2025-06
   검증: 2025-07 ~ 2025-09
   테스트: 2025-10 ~ 2025-12 (최종, 1회만 개봉)

→ 실전(미래 예측) 상황을 그대로 모사
```

### 게이트 B: 공간 교차검증 (Spatial CV)

```
지역(시군구)을 묶어서 fold 분할
→ "옆집 가격 외워서 맞추는" 누수 차단
```

### 게이트 C: 누수 감사 자동화

```python
# scripts/leakage_audit.py (신규 개발)
- 특성-타겟 상관 0.95 초과 → 자동 경고
- 단일 특성 제거 시 R² 0.1 이상 급락 → 누수 의심 플래그
- 미래 타임스탬프 참조 탐지
- comparable 시간 컷오프 위반 탐지
```

### 게이트 D: 0.95 도달 시 "축하 금지, 감사 발동"

```
IF held-out R² ≥ 0.95:
    → 자동 축하 ❌
    → 누수 감사 강제 실행 ✅
    → 3가지 독립 검증 통과 시에만 인정
       1. 시간 분할 테스트셋에서도 유지되는가
       2. 특성 하나씩 제거해도 점진적으로만 하락하는가
       3. 새로운 미공개 지역에서도 유지되는가
```

## 📅 4. 단계별 실행 계획 (로컬 환경, 약 4~6주)

### Phase A: 실데이터 기반 구축 (Week 1~2) → 목표 M1 (0.85)

| 작업 | 산출물 | 검증 |
|------|--------|------|
| Data.go.kr 24개월 실거래 수집 | `data/raw/real_*.csv` (100K+행) | 행수·지역 분포 |
| 거래유형 분리·정합성 검증 | 클렌징 리포트 | 게이트 C |
| 시간 기반 분할 파이프라인 | `scripts/temporal_split.py` | 게이트 A |
| 기본 특성 재학습 | 베이스라인 R² | held-out 평가 |

**게이트**: 시간 분할 테스트셋 R² ≥ 0.85 → 통과 시 Phase B

### Phase B: 고급 특성 공학 (Week 3) → 목표 M2 (0.90)

| 작업 | 기법 | 누수 방지 |
|------|------|-----------|
| 위치 특성 | 지하철/CBD 거리, 동 인코딩 | fold 내 인코딩 |
| 건물 특성 | 층/연식/면적/방향/세대수 | 시점 무관 정적값 |
| 시계열 특성 | 시장지수·계절성 | 시점 이전 정보만 |
| 외부 결합 | 학군·POI·금리 | 공개 시점 확인 |

**게이트**: 공간 CV + 시간 분할 동시 통과, R² ≥ 0.90

### Phase C: 비교사례 + 앙상블 (Week 4~5) → 목표 M3 (0.93)

| 작업 | 위험 | 통제 |
|------|------|------|
| Comparable sales 특성 | 누수 ★★★★★ | 엄격 시간 컷오프 + 게이트 C |
| Optuna 하이퍼파라미터 | 과적합 | nested CV |
| Stacking 앙상블 | 복잡도 | held-out 검증 |

**게이트**: 누수 감사 통과 + held-out R² ≥ 0.93

### Phase D: Stretch — 0.95 도전 및 검증 (Week 6) → M4

```
1. comparable 모델 정밀화 (시공간 가중)
2. 신경망/TabNet 검토 (데이터 충분 시)
3. ⚠️ 0.95 도달 시 게이트 D 강제 발동
4. 3중 독립 검증 통과 → 진짜 인정 / 실패 → 누수로 폐기
```

**최종 게이트**: 미공개 테스트셋(1회 개봉) R² ≥ 0.95 AND 누수 감사 3종 통과

## 📊 5. 성공 기준 (Definition of Done)

```
✅ 진짜 성공 (배포 자격):
   • 시간 분할 테스트셋 R² ≥ 0.95
   • 공간 CV에서도 R² ≥ 0.90 유지 (지역 일반화)
   • 누수 감사 3종 전부 통과
   • 단일 특성 제거 시 급락(0.1+) 없음
   • 예측구간 신뢰도 검증 완료

❌ 가짜 성공 (폐기 대상):
   • 랜덤 K-fold만으로 0.95
   • 특정 특성 제거 시 0.95 → 0.70 급락
   • 미공개 지역에서 0.80 미만
   → 데이터 누수로 간주, 해당 특성 제거 후 재시작
```

## ⚖️ 6. 정직한 리스크 고지

| 시나리오 | 확률 | 대응 |
|----------|------|------|
| 실데이터로 0.85~0.90 도달 | 높음 | M1·M2 정상 달성 |
| 누수 없이 0.93 도달 | 중간 | comparable 정밀화 필요 |
| **누수 없이 0.95 도달** | **낮음~중간** | **comparable 모델 성패에 좌우** |
| 0.95가 사실 누수였음 | **주의** | 게이트 D로 사전 차단 |
| 합성 데이터로 0.95 "달성" | — | **무의미, 실데이터 필수** |

> **경영 보고용 핵심 메시지:**
> "R² 0.95는 가능할 수도 있으나, 그것이 **진짜인지 누수인지 구별하는 검증 체계**가 목표 숫자보다 중요합니다. 본 계획은 숫자를 좇기보다, 미래 실거래에서 무너지지 않는 **0.90+ 신뢰 모델**을 우선 확보하고, 0.95는 엄격한 검증을 전제로 도전합니다."
