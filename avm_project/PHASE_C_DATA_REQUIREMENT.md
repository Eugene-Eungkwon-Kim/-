## 1. 필수 vs 선택 데이터 요구사항

### 1.1 필수 컬럼 (4개 — 반드시 포함)

```
┌─────────────┬──────────────┬────────────┬──────────────────────┐
│ 컬럼명      │ 데이터 타입  │ 범위/값    │ 예시                 │
├─────────────┼──────────────┼────────────┼──────────────────────┤
│ 거래금액    │ 숫자형       │ 양수       │ 350000000            │
│ 거래일      │ 날짜형       │ YYYY-MM-DD │ 2024-01-15           │
│ 면적        │ 숫자형       │ 20~300 ㎡  │ 85.5                 │
│ 지역        │ 문자형/숫자형│ 구분 가능  │ 서울/경기/부산/...   │
└─────────────┴──────────────┴────────────┴──────────────────────┘
```

**핵심 요구:**
- 결측치 없음 (100% 완성도)
- 데이터 타입 정확성
- 실제 거래 기록

### 1.2 권장 컬럼 (6개 — 성능 향상)

```
┌──────────────┬──────────────┬────────────┬──────────────────────┐
│ 컬럼명       │ 데이터 타입  │ 범위/값    │ 기댓값 향상           │
├──────────────┼──────────────┼────────────┼──────────────────────┤
│ 건축년도     │ 숫자형       │ 1960~2024  │ +2~3% R²             │
│ 층수         │ 숫자형       │ 1~50       │ +1~2% R²             │
│ 방개수       │ 숫자형       │ 1~5        │ +0.5~1% R²           │
│ 욕실개수     │ 숫자형       │ 1~3        │ +0.3~0.5% R²         │
│ 엘리베이터   │ 0/1 또는     │ 예/아니오  │ +0.5~1% R²           │
│             │ 문자형       │            │                      │
│ 주차장       │ 숫자형       │ 0~5        │ +0.5~1% R²           │
└──────────────┴──────────────┴────────────┴──────────────────────┘
```

**효과:**
- 4개 필수만: R² ≈ 0.80~0.85
- 4개 필수 + 2개 권장: R² ≈ 0.85~0.90
- 4개 필수 + 6개 권장: R² ≈ 0.90~0.95

## 3. 데이터 수집 방법별 상세 비교

### 3.1 우선순위별 수집 방법

#### 🥇 1순위: 국토교통부 CSV (⭐⭐⭐⭐⭐)

**장점:**
- 가장 빠른 방법 (수동 다운로드)
- 완성도 높음 (90%+)
- 누수 위험 낮음
- 처리 난이도 낮음 (CSV)

**수집 방법:**
```
1. https://rt.molit.go.kr/ 접속
2. "부동산 거래 현황" → "CSV 다운로드"
3. 연도: 2024, 지역: 서울/경기/부산 등 5개+ 선택
4. 다운로드
5. avm_project/data/raw/real_estate_2024.csv 저장
```

**예상 데이터:**
- 행 수: 50,000~200,000 (지역별)
- 기간: 2024년 1월~12월
- 컬럼: 20~30개 (표준화된 구조)

---

#### 🥈 2순위: Data.go.kr 웹사이트 CSV 다운로드 (⭐⭐⭐⭐)

**장점:**
- API 키 불필요 (웹사이트에서 직접)
- 공식 데이터셋
- 완성도 높음 (90%+)

**수집 방법:**
```
1. https://www.data.go.kr/ 접속
2. 검색: "부동산 실거래 정보"
3. 원하는 데이터셋 선택
4. "다운로드" → CSV 선택
5. avm_project/data/raw/real_estate_2024.csv 저장
```

**주의:**
- API 키 방식은 현재 403 오류 (비활성)
- 웹사이트에서 CSV 직접 다운로드는 가능

## 4. 데이터 검증 프로세스

### 4.1 자동 검증 스크립트

**다운로드 후 즉시 실행:**

```bash
python scripts/validate_real_estate_data.py data/raw/real_estate_2024.csv
```

**검사 항목:**
- ✅ 필수 컬럼 확인
- ✅ 행 수 (≥ 5,000)
- ✅ 기간 (≥ 6개월)
- ✅ 결측치율 (< 5%)
- ✅ 거래금액 유효성
- ✅ 거래일 유효성
- ✅ 누수 특성 검사
- ✅ 지역 다양성

### 4.2 검증 통과 기준

| 검사 | 기준 | 필수/권장 |
|------|------|---------|
| 행 수 | ≥ 5,000 | 필수 |
| 기간 | ≥ 6개월 | 필수 |
| 결측치 | < 5% | 필수 |
| 거래금액 | 결측 없음 | 필수 |
| 거래일 | 결측 없음 | 필수 |
| 면적 | 20~300 ㎡ | 필수 |
| 누수 특성 | 없음 | 필수 |
| 지역 다양성 | ≥ 3개 | 권장 |

**통과:** 8개 항목 중 7개 이상 통과

## 5. 데이터 통합 워크플로우

### 5.1 전체 프로세스

```
1단계: 데이터 다운로드
   ↓
2단계: avm_project/data/raw/real_estate_2024.csv 저장
   ↓
3단계: 자동 검증
   python scripts/validate_real_estate_data.py data/raw/real_estate_2024.csv
   ↓
4단계: 검증 통과?
   ├─ YES → 5단계로
   └─ NO → 데이터 전처리 후 재시도
   ↓
5단계: 시간순 평가
   python scripts/temporal_split.py --data data/raw/real_estate_2024.csv --target 거래금액 --time-col 거래일
   ↓
6단계: 누수 감사
   python scripts/leakage_audit.py --data data/raw/real_estate_2024.csv --target 거래금액 --time-col 거래일
   ↓
7단계: 앙상블 재학습
   python scripts/build_ensemble.py --data data/raw/real_estate_2024.csv --target 거래금액 --time-col 거래일
   ↓
8단계: SHAP 분석
   python scripts/shap_analysis.py --data data/raw/real_estate_2024.csv --target 거래금액
   ↓
9단계: Phase C 완료 — 프로덕션 배포
```

### 5.2 예상 결과

| 단계 | 기대값 | 범위 |
|------|--------|------|
| temporal_split | R² ≥ 0.80 | 0.75~0.90 |
| leakage_audit | LEAKAGE_SUSPECTED 또는 CLEAN | 검증 필수 |
| ensemble | R² 평균 | 0.78~0.88 |
| SHAP | 특성 중요도 파악 | 해석용 |

**최종 판정:**
- R² ≥ 0.85: ✅ 배포 가능
- R² = 0.80~0.85: ⚠️ 추가 특성 고려
- R² < 0.80: ❌ 데이터 품질 재검토

## 6. 현재 신호 데이터 vs 실거래 데이터 비교

### 6.1 핵심 차이점

| 특성 | 신호 데이터 | 실거래 데이터 |
|------|-----------|-------------|
| **데이터 소스** | Python 합성 | 실제 시장 거래 |
| **신호 강도** | 매우 강함 (의도적) | 약~중간 (현실적) |
| **노이즈** | 제어됨 (10%) | 예측 불가능 |
| **R² 기대값** | 0.98+ | 0.80~0.90 |
| **누수 위험** | 없음 | 높음 (주의 필요) |
| **시간 범위** | 1년 (2024) | 가변적 |

### 6.2 현재 신호 데이터의 역할

```
✅ 할 수 있는 것:
  • 모델 구조 검증
  • 파이프라인 동작 확인
  • 기술 스택 준비
  • 게이트 검증 프로세스 테스트

❌ 할 수 없는 것:
  • 실제 시장 성능 예측
  • 프로덕션 배포
  • 고객에게 모델 적용
```

**결론:** 신호 데이터는 "기술 검증용", 실거래 데이터가 "실전용"

# 감정가, 평가가, 공시지가 등을 제거하고 다시 시도

### Q: 모델 성능이 기대보다 낮아요 (R² < 0.80)

**A:** 다음 순서로 진행:

1. **검증 게이트 확인**
   ```bash
   python scripts/leakage_audit.py --data data/raw/real_estate_2024.csv --target 거래금액 --time-col 거래일
   ```

2. **특성 추가**
   - 권장 컬럼 (건축년도, 층수, 방개수) 포함 여부 확인
   - 최소 6~8개 특성 사용

3. **데이터 품질**
   - 결측치율 재확인
   - 이상치 제거 고려
