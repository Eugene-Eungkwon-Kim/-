## 📊 프로젝트 구성

### Phase별 구조

```
Phase 1: 기초 정보 정합성 확인 (1일)
  • 5개 시트 기초정보 통합
  • 빌라 시트 부분 재작업 (연번 46% → 100%)
  • 마스터 기초정보 1,085개 생성

Phase 2: 건물 속성 데이터 수집 (2-3일)
  • LG 드라이브 DB 활용 (building_registry.db)
  • Data.go.kr API 보충 수집
  • 전용면적, 준공연도, 층수 등 입력

Phase 3: 가격 데이터 수집 (3-4일)
  • 공시가격 (2023년, 2022년) 수집
  • 실거래 데이터 및 시세 수집
  • 가격 논리 검증 (공시가 < 매매가 < 상단)

Phase 4: AI 예측 계산 (1-2일)
  • AVM 모델 3개 버전 예측 (v1.0, v1.1, vF)
  • 마스예측가 계산
  • 신뢰도 평가

Phase 5: QC 검증 완료 (1-2일)
  • 최종 데이터 검증 (입력률 > 95%)
  • 문서 확인 (O/X) 입력
  • 최종 리포트 작성
```

```
2. 데이터 가용성 확인 필요
   • LG 드라이브 DB 접근 가능한가?
   • API 키 실제 발급 상태 확인 필요
   • Fallback 전략 보강 필요

3. API 신뢰성 보장 필요
   • Rate Limit (0.5초/요청) 준수 확인
   • 403 오류, 타임아웃 대응책 강화
   • 비동기 병렬 호출 도입 권고

4. 모델 성능 목표 조정 권고
   • 현재: R² > 0.85 (보수적)
   • 운영 환경: R² 0.80-0.85 가능성
   • Tier 기준 도입 권고 (Tier 1: 0.80, Tier 2: 0.85)

5. 대응책 보강 필요
   • 데이터 미가용 시 100% API 커버 가능한가?
   • 모델 성능 미달 시 대응책 (재학습, 특성 공학)?
   • 일정 지연 시 우선순위 재조정?
```
