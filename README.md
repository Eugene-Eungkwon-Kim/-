# 모바일 기기 데이터 마이그레이션 & 정리 도구

휴대폰(iPhone, Android)에서 내보낸 파일을 **종류별 + 날짜별**로 자동 분류하고, 파일명을 정리하며, 중복 파일을 찾아냅니다.

---

## 📋 세 가지 스크립트

| 스크립트 | 용도 | 대상 |
|----------|------|------|
| `organize.py` | 기본 파일 정리 | 모든 기기 (일반) |
| `migrate.py` | 모바일 마이그레이션 | Android (ADB) 또는 로컬 폴더 |
| `iphone_migrate.py` | iPhone 전용 | Live Photo / 슬로모션 / 편집본 구분 |

공통 로직은 `phonesort/` 패키지에 있고, 세 스크립트는 그 위에 얹은 얇은 CLI입니다.

---

## ✨ 주요 기능

### 공통
- **종류별 분류**: 사진, 동영상, 음악, 문서, 압축파일, APK, 기타
- **날짜별 분류**: `카테고리/YYYY/MM/` 구조
- **파일명 정리**: `YYYYMMDD_HHMMSS_원본이름.확장자`. 이미 정리된 이름은 다시 붙이지 않습니다(재실행해도 안전)
- **촬영일 우선**: 사진은 EXIF, 동영상은 QuickTime/MP4 메타데이터에서 실제 촬영일을 읽고, 없을 때만 파일 수정 시각을 씁니다
- **중복 탐지**: 같은 내용의 파일을 찾아 한 벌만 남깁니다
- **중단/재개**: 처리 기록을 저널에 남겨, 중간에 멈춰도 다시 실행하면 이어서 진행합니다

### iPhone 전용 (`iphone_migrate.py`)
- **HEIC/HEIF**: `pillow-heif` 설치 시 촬영일까지 읽습니다
- **Live Photo**: 같은 폴더의 `IMG_0001.HEIC` + `IMG_0001.MOV` 쌍을 감지해 **둘 다** `라이브포토/` 로 보냅니다
- **슬로모션 / 타임랩스**: 파일명 패턴으로 구분
- **편집본**: `IMG_E1234` 같은 아이폰 편집본 이름 규칙을 인식해 `편집본/` 으로 분리
- **보고서**: `iphone_migration_report.json`

### Android 전용 (`migrate.py`)
- **ADB 직접 연결**: USB 디버깅으로 기기 파일 자동 추출
- **로컬 폴더 지원**: 기존 백업 폴더 정리
- **보고서**: `migration_report.json`

## 🔐 데이터 안전 규칙

이 도구는 파일을 **이동**시킵니다. 다음 두 가지를 지킵니다.

1. **중복 파일은 기본적으로 삭제하지 않습니다.** `중복/` 폴더로 옮겨두므로, 결과를 확인한 뒤 직접 지우면 됩니다. 곧바로 삭제하려면 `--delete-duplicates` 를 붙이세요.
2. **보존본이 목적지에 안전하게 도착한 뒤에만** 사본을 정리합니다. 보존본 이동이 실패하면 사본은 손대지 않습니다.

그 외에도:
- 목적지에 같은 이름의 **다른** 파일이 있으면 덮어쓰지 않고 `_1`, `_2` 를 붙입니다
- 목적지에 같은 내용이 이미 있으면 다시 옮기지 않습니다
- 이미 정리된 결과물 폴더는 다시 훑지 않습니다 (`organize.py ~/phone ~/phone/정리결과` 처럼 대상이 원본 안에 있어도 안전)

## 🚀 설치

- Python 3.10 이상
- macOS, Linux, Windows

```bash
# 선택 사항 — 촬영일을 정확히 읽으려면 권장
pip install Pillow pillow-heif
```

설치하지 않아도 동작하며, 이 경우 파일 수정 시각으로 분류합니다. 실행 시 어떤 의존성이 빠졌는지 알려줍니다.

> **HEIC 를 쓴다면 `pillow-heif` 를 꼭 설치하세요.** Pillow 단독으로는 HEIC 를 열 수 없어 촬영일을 읽지 못하고, 아이폰에서 내보낸 파일의 수정 시각은 대개 촬영일이 아니라 내보낸 날짜입니다.

## 💻 사용법

### 1️⃣ iPhone

```bash
# 1. iPhone 을 USB 로 연결하고 사진 앱에서 내보내기 (또는 Finder 에서 DCIM 복사)

# 2. 미리보기 — 파일을 건드리지 않고 결과만 보여줍니다
python iphone_migrate.py ~/Desktop/iPhone_내보내기 ~/Desktop/정리결과 --dry-run

# 3. 실제 실행
python iphone_migrate.py ~/Desktop/iPhone_내보내기 ~/Desktop/정리결과
```

### 2️⃣ Android (ADB)

```bash
# 1. Android SDK Platform Tools 설치
# 2. 기기 연결 → 개발자 옵션 → USB 디버깅 허용

python migrate.py --android ./마이그레이션결과
```

### 3️⃣ 로컬 폴더 정리

```bash
python organize.py /path/to/phone_files ./정리결과
python organize.py /path/to/phone_files ./정리결과 --dry-run
```

## ⚙️ 옵션

모든 스크립트가 공통으로 받습니다.

| 옵션 | 설명 |
|------|------|
| `--dry-run` | 미리보기. 파일을 하나도 바꾸지 않습니다 |
| `--delete-duplicates` | 중복 파일을 격리하지 않고 삭제합니다 |
| `--verify` | 이동 후 내용 해시까지 다시 확인합니다 (느림) |
| `--no-resume` | 저널을 무시하고 처음부터 다시 처리합니다 |
| `--workers N` | 해싱 병렬 스레드 수 (기본: 자동) |
| `--prune-empty-dirs` | 정리 후 원본에 남은 빈 폴더를 지웁니다 |

`migrate.py` 전용:

| 옵션 | 설명 |
|------|------|
| `--android` | ADB 로 기기에서 직접 가져오기 |
| `--source 폴더` | 정리할 로컬 폴더 |

## ⚡ 성능

중복 판정은 3단계로 좁혀 실제로 읽는 양을 줄입니다.

1. 파일 **크기**로 그룹핑 — 크기가 유일한 파일은 아예 해싱하지 않습니다
2. 같은 크기끼리만 앞/뒤 64KB **부분 해시**
3. 부분 해시까지 같은 것만 **전체 해시**

해싱은 스레드 풀로 병렬 처리하며, 알고리즘은 blake2b 입니다. 대부분의 백업에서 전체 파일을 읽는 경우는 극히 일부로 줄어듭니다.

## ⚠️ 주의사항

1. **백업 필수**: 원본 파일은 **이동**됩니다. 미리 백업하세요.
2. **미리보기 먼저**: `--dry-run` 으로 결과를 확인한 뒤 실행하세요.
3. **저장 공간**: 같은 디스크 안에서의 이동은 공간을 거의 쓰지 않지만, 다른 디스크로 옮길 때는 원본만큼의 여유가 필요합니다.
4. **`중복/` 폴더 확인**: 삭제하기 전에 내용을 한 번 훑어보세요.

## 🐛 수정 이력

- 중복 파일을 보존본 이동 확인 **전에** 삭제하던 문제 → 순서 교정 및 기본 격리로 전환
- 대상 폴더가 원본 하위일 때 정리 결과물을 다시 집어오던 문제 → 스캔에서 제외
- `DateTimeOriginal` 이 Exif 서브 IFD 에 있어 최상위 IFD 만 훑던 기존 코드로는 읽히지 않던 문제 → 서브 IFD 조회 추가 (촬영일 대신 편집일로 분류되던 증상)
- HEIC 촬영일을 전혀 읽지 못하던 문제 → `pillow-heif` 연동
- 동영상이 항상 파일 수정 시각으로 분류되던 문제 → QuickTime/MP4 컨테이너에서 촬영일 파싱
- Live Photo 의 HEIC 와 MOV 가 서로 다른 폴더로 갈라지던 문제 → 쌍을 함께 `라이브포토/` 로
- 다른 폴더에 있는 같은 이름 파일이 Live Photo 쌍으로 오인되던 문제 → 폴더까지 포함해 판정
- `IMG_E1234`(편집본)를 타임랩스로 분류하던 문제 → `편집본/` 으로 분리
- 이름 충돌 시 `file_1_2_3` 형태로 늘어나던 문제 → 수정
- 정리된 폴더를 다시 정리하면 타임스탬프가 중첩되던 문제 → 멱등 처리
- `_getexif()` deprecated → `getexif()` 로 교체
